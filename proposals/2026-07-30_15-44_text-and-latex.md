# Text and LaTeX primitives

## Goal

Provide one predictable text constructor and one predictable LaTeX constructor with matching anchors, resolved bounds, and ordinary Three.js transform behavior.

## API

```ts
const title = await createText({
  text: "Absorbed power",
  fontSize: 48,
  color: "#ffffff",
  textAlign: "center",
  anchorX: "center",
  anchorY: "middle",
  maxWidth: 600,
  lineHeight: 1.2,
})

const equation = await createLatex({
  latex: String.raw`P = \frac{E}{t}`,
  fontSize: 52,
  color: "#ffffff",
  anchorX: "center",
  anchorY: "middle",
})
```

```ts
type AnchorX = "left" | "center" | "right"
type AnchorY = "top" | "middle" | "bottom" | "baseline"
type TextAlign = "left" | "center" | "right"

interface TextOptions {
  text: string
  fontSize: number
  color?: THREE.ColorRepresentation
  font?: AssetSource
  textAlign?: TextAlign
  anchorX?: AnchorX
  anchorY?: AnchorY
  maxWidth?: number
  lineHeight?: number
}

interface LatexOptions {
  latex: string
  fontSize: number
  color?: THREE.ColorRepresentation
  anchorX?: AnchorX
  anchorY?: AnchorY
}
```

Defaults are identical across both constructors: white, centered horizontally, and anchored at the visual center. Text also defaults to centered line alignment and no wrapping.

`fontSize`, `maxWidth`, and returned local bounds use local scene units. `lineHeight` is a unitless multiplier. A future screen-space layout container may define one local unit as one logical video pixel. Screen measurements always use logical video pixels.

## Alignment

`textAlign` controls how lines are aligned inside multiline text. `anchorX` and `anchorY` control which point of the completed visual is placed at the object's local origin.

Anchors are applied after text shaping, wrapping, or LaTeX rendering. Identical anchor settings therefore have identical placement semantics for text and LaTeX even though their internal renderers differ.

## Ready state

When either constructor resolves:

- fonts and required rendering resources are loaded;
- shaping and wrapping are complete;
- geometry is synchronized;
- anchors are applied;
- local bounds are final.

Bounds must not change asynchronously afterward. Missing fonts, unsupported LaTeX, and invalid bounds are construction errors rather than silent fallbacks.

## Returned objects and measurement

Both constructors return stable Three.js groups implementing the same measurement contract:

```ts
type MeasurableVisual = THREE.Group & {
  getLocalBounds(): THREE.Box2
  getWorldBounds(): THREE.Box3
  getScreenBounds(camera: THREE.Camera): ScreenBounds
}

type TextVisual = MeasurableVisual & {
  setText(text: string): Promise<void>
}

type LatexVisual = MeasurableVisual & {
  setLatex(latex: string): Promise<void>
  part(id: string): LatexPart
}

interface LatexPart {
  visual: LatexVisual
  id: string
}
```

The root group retains its identity when content changes, so scene references, animations, layout relationships, and verifications remain valid.

World bounds are derived from the current world transform. Screen bounds are projected through the supplied camera into the configured logical video resolution.

## Content updates

```ts
await title.setText("Updated title")
await equation.setLatex(String.raw`E = Pt`)
```

An update may replace internal children but must preserve the root object, style, transform, visibility, and authored opacity. The returned promise resolves only after anchors and bounds are final again.

Layout systems depending on the visual are recomputed after a successful update.

## LaTeX-specific capabilities

The unified API standardizes construction, anchoring, measurement, and layout behavior. It does not reduce `LatexVisual` to the capabilities of `TextVisual`.

The new implementation must preserve:

- morphing between LaTeX expressions;
- write and reveal animations;
- marking selected terms;
- highlighting selected terms;
- semantic class and part queries;
- existing particle-based transitions where applicable.

LaTeX-specific effects operate on `LatexVisual` or semantic `LatexPart` handles and return ordinary `AnimationPlan`s:

```ts
const equation = await createLatex({
  latex: String.raw`F = \class{mass}{m}\class{acceleration}{a}`,
  fontSize: 52,
})

scene.addAnims(
  latex.mark(equation.part("mass"), {
    color: "#f97316",
  }),
)

scene.addAnims(
  latex.highlight(equation.part("acceleration"), {
    color: "#38bdf8",
  }),
)
```

`LatexPart` is a semantic ID, not a reference to an internal SVG child. An effect resolves the current rendered children when it binds, so rebuilding or morphing the visual does not invalidate stored selections.

Morph targets are prepared and measured during scene build, while the source state is captured when the animation binds:

```ts
const morph = await latex.morphTo(equation, {
  latex: String.raw`a = \frac{F}{m}`,
  duration: seconds(0.8),
})

scene.addAnims(morph)
```

The stable `LatexVisual` root represents the target expression when the morph completes. Sequential morphs therefore bind from the result of the preceding morph.

Writing, marking, and highlighting are transient effects and do not change intrinsic layout bounds. Morphing keeps layout bounds stable during the transition and adopts the target expression's intrinsic bounds when it completes.

## Animation and layout behavior

Animations target the stable root object. `scaleIn`, `moveTo`, transforms, and opacity animations must preserve the visual's authored scale and material opacity.

The measurement contract is the common input for:

- row, column, and grid layout;
- panel fitting and padding;
- animation origins;
- screen collision checks;
- scene verifications.

## Replaced authoring paths

The primary API replaces:

- `createFastText`;
- `createMeshText`;
- `createChars`;
- standalone `updateText`.

Per-character text access remains advanced. The required LaTeX-specific capabilities operate on the new visual objects but are not alternative constructors.

## Initial scope

The first version intentionally excludes rich spans, gradients, shadows, outlines, automatic panels, responsive typography, and CSS-style objects. It establishes reliable content, alignment, measurement, updates, and interoperability before adding visual effects.
